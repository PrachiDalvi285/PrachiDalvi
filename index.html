Web App

Perselo — Focus Partner Platform

A real-time co-working web app that matches users with focus partners worldwide or pairs them with an AI companion for distraction-free work sessions — complete with streak tracking and ambient sound environments.

perselo.vercel.app — live ↗
PRD · v1.0
Author: Prachi Dalvi
Status: Shipped / Live
Platform: Web (Vercel)

1. Problem Statement

Remote workers, students, and freelancers often struggle with isolation, procrastination, and lack of accountability. Existing productivity tools focus on task management but ignore the social pressure that keeps people focused. Working alongside even a silent stranger has been shown to increase output — yet no accessible product existed to replicate this digitally.

2. Goals & Success Metrics

Goal: Help users enter and sustain deep-work states by providing human or AI accountability in real time.

↑ Session start rate ↑ Avg session length ↑ Day-1 retention Streak continuity %

3. User Stories

As a remote student, I want to work alongside a focus partner so that I stay on task without needing to join a video call.
As a freelancer who works alone, I want an AI companion available when no one else is online so I never feel I'm starting alone.

4. Feature Scope (MVP)

  • Real-time partner matching — auto-connect with another user currently searching
  • AI Companion fallback — instant pairing when no human is available
  • Session goal-setting — user declares intent before starting
  • Streak tracking — daily streak counter to build habit
  • Ambient sound modes — Rain, Café, Ocean, Silent to aid focus
  • Session stats dashboard — sessions today, total minutes, best focus
  • Google OAuth + username persistence — low-friction onboarding

5. Out of Scope (v1)

  • Video/audio calls between partners
  • Team/group sessions
  • Paid tier / premium features

6. Key Trade-offs Made

Chose text-based pairing over video to reduce friction and privacy concerns at MVP stage. Prioritised streak mechanics over advanced analytics — habit-formation is the core value driver. AI companion was scoped as a fallback, not primary, to preserve the human-connection positioning.

IoT · Hardware

Smart Shopping Trolley with Automated Billing

RFID-based retail checkout system that eliminates manual billing. Scoped as an MVP to prove that checkout time could be eliminated for a standard basket, then demoed live to validate the concept.

Product Framing

Problem

Manual checkout at retail counters is slow and error-prone — a major friction point in the customer journey, especially during peak hours. Cashier errors and long queues hurt both customer satisfaction and store throughput.

User Story

As a retail shopper, I want my bill to be calculated automatically as I add items to my cart, so I can skip the checkout queue entirely.

Solution Approach

Scoped an RFID-based MVP: each product carries an RFID tag, the trolley's reader auto-logs items and computes a running total. Requirements included component selection (RFID module, microcontroller), integration of a billing ledger, and a live display for the shopper.

Outcome

Manual billing eliminated Live demo validated Faster checkout proven
Embedded · Control

Self-Balancing Robot

Two-wheeled robot with real-time PID balance correction. Treated as an iterative product: each tuning cycle was a sprint — define stability criteria, run, observe drift, adjust, repeat.

Product Framing

Problem

Two-wheeled robots are inherently unstable — they require continuous real-time correction to remain upright. The challenge was to define "stable" in measurable terms before building, then tune iteratively toward that target.

Agile Approach

Defined stability acceptance criteria upfront (minimal oscillation under 5°, sustained balance for 30s). Each PID tuning cycle acted as a sprint: hypothesize → tune → test → measure → iterate. Data from each run directly informed the next, mirroring a feedback-driven product loop.

Outcome

Stable real-time balance Feedback loop validated 5 iteration cycles
Embedded · IoT

Bluetooth Controlled Car

Wireless RC car with user-experience-first design: the interaction flow was defined before hardware was selected. Stable 8–10m control range, scoped to core functionality to keep the build testable and focused.

Product Framing

Problem

The core user need was reliable wireless control with minimal latency — not raw speed or range. Designed the control interaction flow first, then selected hardware to support that experience rather than defaulting to available components.

Decision

Deliberately scoped to four directional commands only, keeping the interface simple and testable. Chose HC-05 module with UART protocol for reliability within the target 10m range. Deferred advanced features (speed control, obstacle detection) to a potential v2.

Outcome

8–10m stable range Minimal latency MVP scoped cleanly

P1

Alzheimer Care & Tracking Device

Wearable GPS + IoT Safety & Care Management System

Document

Overview & Purpose

A wearable device for Alzheimer's patients that provides real-time GPS tracking, anomaly detection, and carer alerts — enabling safe, semi-independent living while giving caregivers peace of mind. This PRD translates a hardware feasibility study into actionable product requirements.

Problem Statement

Alzheimer's patients face a high risk of wandering and disorientation. Existing solutions (manual supervision, basic GPS trackers) are either intrusive, battery-draining, or lack caregiver-facing interfaces. The gap: a low-power, wearable, real-time system that combines location tracking with behavioural anomaly detection.

Target Users

As a caregiver, I want real-time alerts when the patient exits a safe zone, so I can respond immediately without constant supervision.
As a family member, I want a mobile dashboard showing the patient's current location and recent activity, so I have ongoing peace of mind.

Functional Requirements

  • Real-time GPS location tracking with configurable geofence zones
  • Anomaly detection: irregular movement patterns trigger caregiver alert
  • Low-power BLE + GPS module (Neo-6M / SIM800L) for continuous operation
  • Push notifications to caregiver app on geofence breach
  • Fall detection via accelerometer data
  • Battery life ≥ 24 hours under active tracking
  • Wearable form factor: wrist or pendant-compatible

Non-Functional Requirements

  • Location accuracy: ≤ 10m under clear sky
  • Alert latency: ≤ 30 seconds from trigger to caregiver notification
  • Device weight: ≤ 80g for wearability
  • Data privacy: location data encrypted in transit and at rest

Constraints & Feasibility Notes

GPS accuracy degrades indoors — hybrid BLE beacon fallback required for indoor environments. SIM800L requires cellular coverage; offline mode must cache last-known location. Hardware prototype validates component compatibility before software integration.

Success Metrics (KPIs)

Alert delivery < 30s Battery > 24hr Caregiver response rate ↑ Zero missed geofence events
P2

Sign Language Translator Glove

Standalone Wearable Gesture-to-Speech Communication Device

Document

Overview & Purpose

A wearable glove that translates hand gestures from sign language into spoken words in real time — enabling speech-impaired individuals to communicate naturally with hearing people without requiring an interpreter or companion device.

Problem Statement

The 70+ million deaf and speech-impaired people worldwide face daily communication barriers. Interpreter services are costly and unavailable in most everyday contexts. Existing solutions require a paired smartphone or are too expensive for widespread adoption. The gap: an affordable, self-contained, real-time gesture-to-speech device.

Target Users

As a speech-impaired person, I want to communicate my intended words directly to others, so I don't need an interpreter present in everyday situations.
As a healthcare worker, I want to understand a non-verbal patient's basic needs, so I can provide appropriate care quickly.

Functional Requirements

  • Flex sensor array on each finger captures gesture angle in real time
  • MPU-6050 accelerometer/gyroscope captures hand orientation and motion
  • On-device ML model classifies gesture → mapped word/phrase
  • Text-to-speech module outputs recognised word audibly within 500ms
  • LCD display shows recognised text for environments where audio is inappropriate
  • Minimum gesture vocabulary: 26 alphabets + 50 common phrases
  • Standalone operation — no paired smartphone required

Non-Functional Requirements

  • Recognition accuracy: ≥ 90% on trained gesture set
  • Response latency: ≤ 500ms from gesture to audio output
  • Form factor: full glove, comfortably wearable for 4+ hours
  • Battery: ≥ 8 hours continuous use on single charge

Constraints & Feasibility Notes

Flex sensor accuracy varies with individual hand size — calibration routine required at first use. On-device inference constrained by microcontroller memory; model must be quantised (TFLite). Ambient noise degrades TTS intelligibility — display fallback is essential requirement, not nice-to-have.

Success Metrics (KPIs)

≥ 90% accuracy Latency ≤ 500ms 8hr battery life 50+ phrase vocabulary
